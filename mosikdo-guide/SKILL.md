# 모식도 가이드 (macOS Schematic Guide)

macOS(Apple HIG) 룩앤필의 HTML 가이드 문서를 만들고, 말로 설명하기 어려운
핵심 개념을 **인라인 SVG 모식도**로 시각화하는 디자인 시스템이다. 데스크톱 위에
떠 있는 윈도우(트래픽 라이트 + 반투명 툴바) 안에, 번호가 매겨진 섹션과 컬러가
의미를 나르는 다이어그램을 배치한다.

이 스킬의 핵심 가치는 **매번 CSS와 SVG 패턴을 새로 짜지 않는 것**이다. 검증된
토큰 시스템과 컴포넌트/모식도 스니펫이 번들로 들어 있으니, 그것을 뼈대로 삼아
내용만 채운다.

## 언제 쓰는가

- 분석 파이프라인·워크플로우·의사결정 흐름·분류 체계를 설명하는 가이드 문서
- "왜 이건 안 되는가", "이 방식과 저 방식의 차이" 같이 **흐름·대비**로 이해시켜야 하는 개념
- macOS 감성의 깔끔하고 읽기 좋은 문서를 원할 때
- 이미 만든 모식도 가이드를 이어서 수정·확장할 때

## 산출물 형태

- 단일 HTML 파일. Claude Artifact로 게시하기도 하고(그때는 `<!doctype>/<html>/<head>/<body>`
  래퍼 없이 `<title>` + `<style>` + 본문만), 로컬 `.html`로 저장하기도 한다.
  브라우저에서 래퍼 없이도 정상 렌더링된다.
- 라이트/다크 모드 모두 대응(뷰어 테마 토글 포함).
- 모바일에서 본문은 가로 스크롤이 없어야 하고, 넓은 모식도·표는 자체 컨테이너
  안에서만 가로 스크롤된다.

## 작업 순서

1. **구조부터 잡는다.** 내용을 섹션으로 나눈다. 보통 이 순서가 잘 맞는다:
   ① 원리/핵심 전제 → ② 의사결정·분기 → ③ 각 방식 상세 → ④ 비교표 → ⑤ 체크리스트.
   섹션마다 번호 칩(`.sec-num`)과 mono 키커(`.kicker`)를 단다.

2. **모식도가 필요한 곳을 고른다.** 모든 것을 그리지 않는다. 글보다 그림이 확실히
   나은 지점 — 흐름(A→B→C), 분기(트리), 대비(된다 vs 안 된다), 누적/편차 —
   에만 SVG를 넣는다. 나머지는 콜아웃·리스트·표로 처리한다.

3. **템플릿을 복사해 시작한다.** `assets/template.html`의 `<style>` 블록과 상단
   숨김 SVG defs(화살표 마커), `.desktop`/`.window`/`.titlebar`/`.content` 뼈대를
   그대로 가져온다. 토큰과 클래스는 손대지 말고 본문만 채운다.

4. **컴포넌트를 조립한다.** 콜아웃, 조건 카드, 방식(method) 블록, 리스트, 예시,
   비교표, 체크리스트의 정확한 마크업은 `references/components.md`를 본다.

5. **모식도를 그린다.** 흐름 노드·화살표·금지 기호·비교 패널·의사결정 트리 등
   복붙 가능한 SVG 스니펫과 공유 `.dg` 클래스 규약은 `references/diagrams.md`를 본다.

6. **게시/저장.** Artifact로 게시할 때는 같은 favicon(예: 🧬 또는 주제에 맞는 이모지)을
   유지하고, 로컬 저장을 원하면 작업 폴더로 복사한다.

## 반드시 지키는 원칙

**컬러는 장식이 아니라 의미다.** 이 시스템의 힘은 색이 일관된 뜻을 갖는 데서
나온다. 문서 전체에서 아래 매핑을 흐트러뜨리지 않는다:

| 의미 | 토큰/클래스 | 쓰임 |
|---|---|---|
| 신규 생성 · 기준 만들기 | `--accent` (파랑) | Assembly 노드, 핵심 단계 |
| 최종 기준 서열/결과 | `--accent` solid | "이게 좌표계다" 강조 |
| 생략되는 단계 | `--ink-3` + 점선(dashed) + 취소선 | 건너뛰는 과정 |
| 가능 · 성공 | `--green` | "DEG 가능", 정상 조립 |
| 주의 · 부분적 | `--orange` | 누락 위험, 품질 저하 |
| 불가 · 실패 | `--red` + 금지 기호(⊘) | "비교 불가", 병합 불가 |

서로 다른 대상(샘플군 A vs B, 조직 잎/줄기/뿌리 등)은 파랑/보라/주황/시안/핑크
계열로 구분하되, 위 의미색(green/orange/red)과 겹치지 않게 쓴다.

**테마는 토큰으로만 바꾼다.** 색을 컴포넌트에 직접 박지 말고 `:root`의 CSS 변수로
정의한 뒤, `@media (prefers-color-scheme: dark)`와 `:root[data-theme="dark"]`/
`[data-theme="light"]` 세 곳에서 토큰만 재정의한다. 다크 모드는 단순 반전이 아니라
대비가 살아 있게 별도로 조정한다(템플릿에 이미 반영됨).

**SVG 텍스트는 vector-effect가 아니라 큰 좌표로.** 모식도는 `viewBox`로 그리고
`width:100%`로 표시한다. 너무 작은 폰트(9px 미만)는 피하고, 넓은 그림은
`.fig-scroll`(min-width + overflow-x)로 감싸 모바일에서 스크롤되게 한다.

**모식도 스타일을 통일한다.** 노드는 둥근 사각형(rx 11~13), 화살표는 하나의 공유
마커(`#ah`)를 재사용, 라벨/제목/캡션은 `.lbl`/`.ttl`/`.cap` 클래스로. 색을
`var(--...)`로 채워 테마를 따라가게 한다. 스니펫은 `references/diagrams.md` 참고.

**본문은 절대 가로 스크롤 금지.** 표·모식도만 자기 컨테이너에서 스크롤한다.
넓은 다이어그램에는 `.scroll-hint`("← 좌우 스크롤")를 모바일에서 노출한다.

## 자주 하는 실수

- 색을 예쁘라고 아무 데나 쓰기 → 의미 매핑이 깨지면 독자가 혼란스럽다.
- 모든 문단을 그림으로 → 흐름/분기/대비가 아닌 내용은 리스트·콜아웃이 더 빠르다.
- 다크 모드 확인 누락 → 토큰만 썼는지, 하드코딩된 `#fff`/`#000`이 없는지 본다
  (단, SVG 노드 안 흰 글자처럼 의도된 것은 예외).
- 화살표 마커를 그림마다 새로 정의 → 상단 숨김 defs의 `#ah` 하나만 재사용한다.

## 레퍼런스

- `assets/template.html` — 전체 CSS 토큰 시스템 + 윈도우 뼈대 + SVG defs + 예시 섹션.
  **여기서 복사해 시작한다.**
- `references/components.md` — 콜아웃/카드/방식 블록/리스트/예시/표/체크리스트 마크업.
- `references/diagrams.md` — 모식도 SVG 패턴(흐름·금지·비교·트리)과 `.dg` 클래스 규약.
- `assets/example-denovo.html` — 이 시스템으로 완성한 실제 가이드(De novo 전사체 분석,
  Assembly Group 설정). 섹션 구성(원리→결정 트리→방식 상세→비교표→체크리스트)과
  모식도 7패턴이 문맥 속에서 어떻게 쓰이는지 보여주는 **기준 예시**. 새 가이드를
  만들 때 밀도·톤·모식도 배치의 레퍼런스로 삼되, 그대로 베끼지 말고 주제에 맞게 재구성한다.
