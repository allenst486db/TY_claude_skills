Claude Code 스택 통합 가이드

플러그인 9 · 스킬 4 · MCP 서버 2 = 15개 항목. 이 문서 하나가 전체 스택의 설치 · 사용 · 현재 상태를 담는다. 기계가 읽는 명세는 claude-stack.json, 재현은 scripts/install-claude-skills.*.

이 문서가 대체한 것

이전에 나눠져 있던 claude-skills-setup-guide.html · claude-skills-setup-guide.md · claude-tools-5-guide.html 세 문서를 하나로 합쳤다. 내용이 어긋나던 부분은 실제 설치에 성공한 상태를 기준으로 정리했다.

Install

설치 경로는 다섯 갈래, 도착지는 하나

배포 방식이 항목마다 다르지만 전부 전역 ~/.claude로 모인다. 그래서 이 저장소를 포함한 모든 프로젝트에서 별도 설정 없이 쓸 수 있다.

새 머신에서 한 번에 재현

저장소 루트 — Terminal
git clone <이 저장소> && cd <저장소>

# Windows
pwsh -File scripts/install-claude-skills.ps1

# macOS / Linux / Git Bash
bash scripts/install-claude-skills.sh

스크립트는 멱등이라 여러 번 돌려도 안전하고, 이미 있는 항목은 건너뛴다. settings.json·CLAUDE.md는 덮어쓰지 않고 추가만 한다.

Windows PATH 함정 — pip 경로

pip 는 실행 파일을 %APPDATA%\Python\Python314\Scripts 에 넣는데 이 경로가 PATH 에 없었다. 사용자 PATH 에 append 해 뒀다(기존 값 유지). 새 터미널부터 graphify·notebooklm·yt-dlp 가 잡힌다.

이미 열린 셸에서는 $env:Path += ';C:\Users\allen\AppData\Roaming\Python\Python314\Scripts' 로 임시 적용.

새로 설치한 스킬·플러그인은 Claude Code 를 재시작해야 커맨드가 등록된다.

2경로

NotebookLM — MCP 서버 + Python CLI

로그인 필요

같은 서비스에 붙는 두 개의 다른 도구가 설치돼 있다. 하나는 대화 중 호출하는 MCP 서버, 하나는 스크립트로 돌리는 Python CLI 다. 인증은 각각 따로 한다.

대화형 질의는 MCP, 반복·배치는 CLI/Python. 아티팩트 종류는 CLI 쪽이 넓다.

notebooklm — 인증 & 기본 사용
# 인증 — 셋 중 하나. (a) 가 가장 단순
notebooklm login                                  # (a) Playwright 창에서 로그인
notebooklm login --browser-cookies chrome          # (b) 기존 Chrome 쿠키
notebooklm login --master-token --account you@example.com  # (c) 만료 자동 갱신

notebooklm auth check --test --json               # 확인 — 모든 행 통과해야 함

# 기본 워크플로
notebooklm create "2026 리서치"
notebooklm source add "https://example.com/paper"
notebooklm source add "./report.pdf"
notebooklm ask "핵심 주장 세 개만 뽑아줘"

# 아티팩트 — --wait 로 완료까지 블로킹
notebooklm generate audio --wait
notebooklm generate video --style whiteboard --wait
notebooklm generate quiz
notebooklm download audio ./podcast.mp3
research.py — async Python API
import asyncio
from notebooklm import NotebookLMClient

async def main():
    async with NotebookLMClient.from_storage() as client:
        nb = await client.notebooks.create("Research")
        await client.sources.add_url(nb.id, "https://example.com")
        result = await client.chat.ask(nb.id, "요약?")
        print(result.answer)

asyncio.run(main())
비공식 API 라는 뜻

내부적으로 Google 의 문서화되지 않은 batchexecute RPC를 쓴다. Google 이 메서드 ID 를 바꾸면 예고 없이 깨진다. 프로덕션 의존성으로 쓰지 말고, 깨졌을 때 손으로 대체 가능한 작업에만 걸어라.

deep-research — 인용이 붙는 리서치

바로 사용

여러 소스를 교차 검증하고 근거를 파일로 남겨 인용이 붙은 리포트를 만든다. 검색 1~2회로 끝나는 질문에는 쓰지 않는다(스킬 자체가 거절하도록 설계됨).

Claude Code — 자연어 트리거
deep research on 2026년 국내 전기차 보조금 정책 변화
deep research in ultradeep mode: Postgres vs. ClickHouse 분석 워크로드 비교
모드단계steps소요용도
quick32–5분초기 탐색
standard610–20분일반 리서치
deep830분+의사결정용 리포트
ultradeep8+그 이상정밀 비교·검증
  • 리포트는 ~/Documents/[주제]_Research_[날짜]/에 Markdown / HTML / PDF 로 저장된다.
  • 필수 의존성 없음 — Python 3.9+ 표준 라이브러리만 쓴다.
  • 선택: weasyprint(PDF), search-cli(Brave·Serper·Exa·Jina·Firecrawl 집계 — API 키 필요).
  • 권한 프롬프트가 잦다 — 줄이려면 ~/.claude/settings.json의 permissions.allow에 WebSearch·Glob·Grep·Read를 추가한다. WebFetch 자동 승인은 임의 URL 접근을 무확인 허용하므로 판단 후 적용. 이번에도 적용하지 않았다.

② Codebase

graphify — 폴더를 질의 가능한 지식 그래프로

RAG 처럼 들리지만 벡터 스토어가 없다. tree-sitter 로 25개 언어의 AST 를 실제로 파싱해 노드와 엣지를 만들고 모든 엣지에 근거가 붙는다. 임베딩 유사도 추측이 아니라 결정론적 파싱이라는 게 이 도구의 정체성이다.

Claude Code — /graphify
# 처음 한 번
/graphify .

# 대상·모드 지정
/graphify ./src --mode deep      # 엣지를 더 적극적으로 추출
/graphify ./src --update         # 바뀐 파일만 재추출 (빠름)
/graphify ./src --watch          # 파일 변경 시 자동 동기화
/graphify ./docs --wiki         # 위키 스타일 문서 생성

# 질의
/graphify query "결제 검증은 어디서 일어나?"
/graphify path "AuthService" "PaymentWebhook"
  • 큰 저장소부터 쓰지 마라 — 하위 폴더 하나로 감각을 잡고 범위를 넓힌다.
  • --update를 습관화 — 전체 재추출은 느리다. 변경분만은 몇 초.
  • 패키지 이름 주의 — PyPI 는 graphifyy(y 두 개), CLI·슬래시 커맨드는 graphify. 이름 반환 절차 중이라 그렇다.
  • graphify install이 ~/.claude/CLAUDE.md를 건드린다 — 트리거 한 줄을 append 한다. 이 머신에서는 기존 Astryx 블록이 유지된 것을 확인했다.

impeccable v4.0.2

init 필요

LLM 이 뽑는 UI 는 기능은 되는데 어딘가 뻔하다. 그 뻔함을 58개 결정론적 디텍터 룰로 잡고, 23개 커맨드로 계획 → 만들기 → 감사 → 비평 → 다듬기 순환을 강제한다.

audit(기술 품질)과 critique(디자인 판단)는 다른 축이다 — 둘 다 돌려야 한다.

프로젝트별 1회 필수

ponytail v4.8.4

바로 사용 · 기본 full

전제가 하나다 — 가장 좋은 코드는 안 쓴 코드다. 코드를 쓰기 전에 7단 결정 래더를 강제로 훑게 한다. 위쪽 단에서 끝날수록 싸다.

ponytail 은 이 래더를 건너뛰지 못하게 한다 — 7번으로 바로 뛰는 게 LLM 의 기본 습관이다.

상시

karpathy-guidelines v1.0.0

바로 사용

Karpathy 가 지적한 LLM 코딩의 전형적 실패 패턴을 규칙으로 만든 스킬. 코드를 쓰거나 리뷰·리팩터링할 때 자동으로 걸린다.

  • Think Before Coding — 가정을 명시하고, 해석이 여러 개면 다 꺼내놓고, 모르면 멈추고 묻는다.
  • Simplicity First — 요청된 것만. 1회용 코드에 추상화 금지, 불가능한 예외의 에러 처리 금지.
  • Surgical Changes — 건드려야 할 것만. 옆 코드 "개선"·포맷 정리 금지.
  • Goal-Driven Execution — 검증 가능한 성공 기준을 먼저 정의한다.
  • 트레이드오프 — 속도보다 신중함 쪽. 사소한 작업에서는 답답할 수 있다.

관사·군말·인사말·완충 표현을 걷어내고 문장 조각으로 답하게 만들어 출력 토큰을 약 65% 절감한다. 코드·명령어·에러 메시지는 건드리지 않는다.

설정 파일 한 줄이 분기를 결정한다. 지금은 초록 경로로 고정돼 있다.

%APPDATA%\caveman\config.json
{
  "defaultMode": "off"
}
명령설명
/caveman [lite·full·ultra·wenyan]압축 강도 전환
/caveman-commit50자 이하 컨벤셔널 커밋 메시지
/caveman-review한 줄짜리 PR 코멘트
/caveman-stats세션·누적 토큰 절감량
/caveman-compress <file>메모리 파일 압축 (입력 토큰 ~46% 절감)

모드 우선순위

CAVEMAN_DEFAULT_MODE 환경변수 → 저장소별 .caveman/config.json → 사용자 설정 → 기본값(full). 프로젝트 단위로 항상 켜려면 그 저장소에 .caveman.json을 둔다.

알려진 문제 3

① ffmpeg 미설치 — /watch 미동작

yt-dlp는 설치됐지만 ffmpeg 가 없다. 프레임 추출이 안 되므로 /watch가 동작하지 않는다. 서드파티 패키지 라이선스 동의가 붙어 자동 설치하지 않았다.

해결: winget install Gyan.FFmpeg → 새 터미널에서 ffmpeg -version 확인.

② NotebookLM 인증 미완료

notebooklm auth check가 실패 상태다(storage_state.json 없음). 브라우저 창에서 Google 로그인이 필요하고, 이건 사람이 직접 해야 한다.

해결: notebooklm login → 확인 notebooklm auth check --test.

③ notebooklm MCP 스코프 중복

notebooklm MCP 서버가 user 와 local 두 스코프에 서로 다른 엔드포인트로 등록돼 있다(npx -y notebooklm-mcp@latest vs npx notebooklm-mcp@latest). 인증 토큰은 엔드포인트별로 저장되므로 한쪽에서 인증해도 다른 쪽에 적용되지 않는다.

권장: user 스코프(스크립트가 재현하는 쪽)를 남기고 local 을 제거 — claude mcp remove notebooklm -s local. 인증 상태가 날아갈 수 있으니 로그인 전에 정리하는 게 낫다.
