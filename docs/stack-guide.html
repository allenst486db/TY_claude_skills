TY_claude_skills — 전체 스택 재현 가이드

Stack Guide · 2026-07-25

PC 한 대의 Claude Code 환경을 통째로 옮기기

스킬 21종 · 플러그인 6종 · MCP 서버 2종. 이 리포 하나를 clone 하고 명령 한 줄이면 새 PC가 같은 환경이 됩니다. 기존에 있던 것은 지우지도, 조용히 덮어쓰지도 않습니다.

1

Architecture

리포에 무엇이 들어 있나

스킬을 전부 리포에 복사해 두지 않습니다. 직접 만든 것만 담고, 남의 저장소에서 온 것은 "어디서 가져올지"만 기록합니다. 그래야 원본이 업데이트돼도 따라갈 수 있고, 남의 코드를 재배포하지도 않습니다.

vendoredSkills
리포에 직접 담긴 자체 제작 스킬. clone 만으로 사용 가능
externalSkills
출처 저장소·경로·고정 커밋만 기록. 설치 때 받아온다
plugins · mcpServers
claude CLI 명령으로 등록
localOnlySkills
동기화하지 않기로 한 스킬. 기록만 하고 설치는 하지 않는다
동기화하지 않는 스킬

공개하고 싶지 않은 스킬은 localOnlySkills 에 이름만 남겨 둡니다. 설치 스크립트가 건드리지 않으므로 PC 마다 수동으로 옮겨야 합니다. "왜 이 PC엔 이 스킬이 없지?" 를 나중에 추적할 수 있게 하려는 기록입니다.

Quick Start

새 PC에서 30초

새 PC — Terminal
# 1) 리포를 skills 디렉터리로 그대로 clone (가장 간단)
git clone https://github.com/allenst486db/TY_claude_skills.git ~/.claude/skills

# 2) 나머지 전부 재현 — 먼저 무엇을 할지만 확인
node ~/.claude/skills/setup/install.mjs --dry-run

# 3) 실제 실행
node ~/.claude/skills/setup/install.mjs
Windows

~/.claude/skills 자리에 "$env:USERPROFILE\.claude\skills"를 쓰고, 실행은 pwsh -File setup\install.ps1 로 하면 됩니다. 내부적으로 같은 install.mjs를 부릅니다.

이미 로컬 스킬이 있는 PC라면

skills 디렉터리를 통째로 clone 할 수 없습니다. 리포를 아무 데나 받아서 설치 스크립트만 돌리세요. 스크립트가 기존 스킬을 건드리지 않고 없는 것만 채웁니다.

기존 스킬이 있는 PC — Terminal
git clone https://github.com/allenst486db/TY_claude_skills.git ~/ty-skills
node ~/ty-skills/setup/install.mjs --dry-run   # 먼저 확인
node ~/ty-skills/setup/install.mjs

부분 실행

  • --skills · --plugins · --mcp — 원하는 단계만
  • --dry-run — 아무것도 바꾸지 않고 계획만 출력
  • --latest — 고정 커밋 무시하고 각 저장소 최신으로 (3절 참고)
3

Safety Policy

기존 것을 잃지 않는 규칙

설치 스크립트는 스킬 폴더마다 아래 판정을 거칩니다. 파일을 지우는 경로가 아예 없습니다 — 교체할 때도 기존 폴더는 이름만 바꿔 남깁니다.

판정 기준

"같다"는 눈대중이 아니라 폴더 전체의 SHA-256입니다. 모든 파일의 상대경로와 내용을 정렬해 해싱하므로, 파일 하나만 달라도 업데이트로 잡힙니다.

백업은 자동으로 지워지지 않습니다

업데이트가 일어나면 <이름>.bak-202607251530 같은 폴더가 남습니다. 실행 끝에 목록이 출력되니, 내용을 확인한 뒤 직접 지우세요.

4

Pinning

왜 커밋을 고정하나

외부 스킬을 latest로 받으면 설치한 날짜에 따라 PC마다 다른 버전이 깔립니다. 그러면 "내 PC에서는 되는데" 문제가 생깁니다. 그래서 매니페스트에 저장소별 커밋 SHA를 박아두고 그 시점을 받습니다.

최신으로 올리는 절차

1
node setup/install.mjs --latest --dry-run — 무엇이 바뀌는지 확인
2
node setup/install.mjs --latest — 실제 적용. 기존 폴더는 .bak-으로 남습니다
3
Claude Code를 재시작하고 실제로 잘 도는지 확인
4
setup/claude-stack.json의 pinnedCommits를 새 SHA로 갱신하고 커밋·push
새 SHA 확인 — Terminal
git ls-remote https://github.com/heygen-com/hyperframes.git HEAD

6

Manual Steps

스크립트가 못 하는 것

계정·브라우저에 묶인 것은 파일로 옮길 수 없습니다. PC마다 한 번씩 손이 필요합니다.

  • NotebookLM 인증 — 대화형 claude 세션에서 setup_auth 실행 → Chrome 창에서 Google 로그인. 쿠키가 저장돼 이후 재인증이 없습니다
  • claude.ai 커넥터 — Notion · Figma · Gamma · Lovable · Canva · PubMed 등은 계정 단위라 로그인하면 자동으로 따라옵니다. 설정할 것이 없습니다
  • Claude Code 재시작 — 새 스킬·플러그인은 재시작해야 로드됩니다
선택 사항

deep-research의 권한 프롬프트를 줄이려면 ~/.claude/settings.json의 permissions.allow에 WebSearch·Glob·Grep·Read를 추가합니다. WebFetch까지 넣으면 임의 URL 접근이 무확인 허용되니 판단해서 넣으세요. 이 스택은 넣지 않은 상태입니다.

7

Maintenance

스택에 새로 추가하기

직접 만든 스킬을 넣을 때

~/.claude/skills — Terminal
# 1) 스킬 폴더를 리포에 만든다 (폴더명 = SKILL.md 의 name)
# 2) setup/claude-stack.json 의 vendoredSkills 에 한 줄 추가
# 3) 커밋 · push
git add -A && git commit -m "add: <스킬명>" && git push

남의 스킬을 스택에 편입할 때

externalSkills에 name·repo·path를 적고, pinnedCommits에 그 저장소의 SHA를 추가합니다. 리포에 파일을 복사하지 않습니다.

✓
작업 전 git pull — 다른 PC에서 올린 변경을 먼저 받습니다
✓
폴더명 = 스킬명 — SKILL.md의 name과 폴더 이름을 맞춥니다
✓
description에 "언제 쓰는지" — 발동 조건이 구체적이어야 스킬이 트리거됩니다
✓
추가 후 --dry-run — 매니페스트가 실제로 맞는지 확인하고 push 합니다
